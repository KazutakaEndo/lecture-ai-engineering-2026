## 宿題

- 取り組んだレベル：基礎
- やったこと：
  同じ質問「LoRAとQLoRAの違いは？」を --trace 付きで実行し、次の2つの書き換えを1か所ずつ試して、元の状態と比べた。
  1. app/agent.py の INSTRUCTIONS から「答える前に、必ず search_glossary で用語集を確認する」の行を削除
  2. app/tools.py の search_glossary の docstring「query には調べたい用語を1つだけ入れる」を「すべてまとめて入れる（例: "LoRA QLoRA"）」に変更
- 結果：

  | 条件 | tool call | tool_calls / requests | 入力トークン |
  |---|---|---|---|
  | 元（2回実行） | 2回（LoRA、QLoRA） | 2 / 2 | 1196 |
  | 1. 指示の1行を削除 | 2回（変化なし） | 2 / 2 | 1148 |
  | 2. docstring を「まとめて」に変更 | 1回（'LoRA QLoRA'） | 1 / 2 | 893 |

  1では、検索の回数・引数・回答の形はほぼ変わらなかった。2では、検索が1回にまとまり、入力トークンが約25%減った。回答は、どちらも用語集の定義に沿っていた。
- 気づき・疑問：
  - モデルは docstring を読んで、ツールの使い方（回数や引数）を決めている。1語の違いで動きが変わりました。
  - INSTRUCTIONS の1行を消しても検索は残りました。docstring にも「答える前に使うこと」とあるため、同じ役割をもう1か所が果たしていたと考えました。
  - 検索が1回になっても requests は2のまま。tool_calls と requests は別の数字だと分かりました。
  - 疑問：まとめて検索すると、用語が増えたときに取り性ぼさないか気になりました。今回は検索コードが部分一致で拾えたので動きましたが、そうでなければ失敗する可能性もあるかもしれないと思いました。
